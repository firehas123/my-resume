# Muhammad Hassan Chattha: resume and portfolio

My personal site, built with Next.js (App Router, TypeScript), plain CSS Modules
with CSS variables, Motion for scroll and hover animation, and one optional
React Three Fiber object in the hero.

## Commands

| Command         | What it does                                                                 |
| --------------- | ---------------------------------------------------------------------------- |
| `npm install`   | Install dependencies (once, and after pulling changes to `package.json`).    |
| `npm run dev`   | Development server on port 3000, reachable from other devices on the network. |
| `npm run build` | Production build (this is what Vercel runs).                                  |
| `npm run start` | Serve the production build locally.                                           |
| `npm run sync`  | Refresh `src/data/projects.json` from GitHub (needs the `gh` CLI, logged in). |
| `npm test`      | Test the rules that sort repos into language tabs.                            |
| `npm run lint`  | Check the code with ESLint.                                                   |

Requires Node.js 20.9 or newer.

### Preview on another device (for example a Mac on the same Wi-Fi)

`npm run dev` listens on all network interfaces. Open `http://<this machine's IP>:3000`
on the other device, for example `http://192.168.0.67:3000`. If the IP changes,
also update `allowedDevOrigins` in `next.config.ts`.

## Common changes

### Update my details

Edit `src/data/profile.json`. Anything still marked `TODO` shows up highlighted on the
site, so it is easy to spot.

- **Switch the CV file:** put the new PDF in `public/files/` and change `"cv": { "path": ... }`,
  for example to `"/files/europass-cv.pdf"`. That one line updates every Download CV button.
- **Show or hide a profile link:** set `"show": true` or `false` on the link (Fiverr is
  currently `false`).

### Refresh projects from GitHub

```bash
npm run sync      # rewrites src/data/projects.json and SYNC-REPORT.md
npm test          # optional: checks the grouping rules still behave
git add src/data/projects.json SYNC-REPORT.md && git commit -m "chore: sync projects" && git push
```

The sync prints a table of every repo with its top languages, the group it was put in
and why, plus a list of skipped forks. The same is saved to `SYNC-REPORT.md`, so you can
check the result before committing.

Which repos are shown:

- **Private repositories never appear**, not on the site and not in the report.
- **Empty repositories** are skipped.
- **Forks** are shown only if my copy has **commits of my own** that the original does
  not have. The sync compares my default branch with the original's (GitHub's "ahead
  by" count). Forks without my own commits stay hidden. Shown forks get a small
  **Fork** label on the card, and their project page says "Fork of owner/repo".
  `overrides.json` can force either way with `"include": true` or `"hide": true`.
  `SYNC-REPORT.md` lists every skipped fork and why.
- A fork keeps the original's description and website until you change them on GitHub.
  While they are still identical to the original's, they describe the original, not your
  work, so they are not shown. Add a `summary` or `demo` in `overrides.json`, or edit the
  fork's description on GitHub.
- A repo's GitHub "Website" field becomes its **Live demo** link.

### How projects are grouped into tabs

GitHub labels every repo with one "primary language", which is often misleading (a
notebook project is "Jupyter Notebook", a web app is often "HTML"). So the sync looks at
each repo's **full language breakdown** instead:

1. **Ignore what isn't project code**: HTML, CSS, SCSS, Makefile, CMake, Dockerfile,
   Shell, Batchfile, TeX and similar.
2. **Merge related languages**:
   - Jupyter Notebook counts as **Python**
   - C and C++ form **C / C++**
   - JavaScript and TypeScript form **JavaScript / TypeScript**
3. The group with the **largest share** of the remaining code wins. A tie goes to the
   group that comes first in the tab order.
4. If nothing is left after step 1 (for example an HTML-only site), the repo goes to
   **Other**.
5. A `"group"` set in `overrides.json` **always wins** over the automatic choice.

Any other language becomes its own group (for example Java, or Go). There is one tab
for every group that has at least one project. Tab order: **C / C++, Python, Java,
JavaScript / TypeScript**, then any others A–Z, and **Other** last. Groups without
projects get no tab.

The rule lists (ignored languages, merges, tab order) live in
`src/data/language-groups.json`, so you can adjust them without touching code. The
logic is in `scripts/lib/grouping.mjs`, with tests in `scripts/grouping.test.mjs`
(`npm test`).

Each project card shows its group plus its top two or three languages as small labels.
The project page shows the same, with percentages.

### Change a project without touching GitHub

Add an entry to `src/data/overrides.json`, keyed by the exact repo name:

```json
{
  "Advanced-Account-Management-System": {
    "title": "Account Management System",
    "summary": "One line about what it does.",
    "group": "C / C++",
    "demo": "https://example.com",
    "featured": true,
    "order": 1
  },
  "made-project-ws2024": { "include": true },
  "SLU": { "hide": true }
}
```

All fields are optional:

| Field | What it does |
| --- | --- |
| `hide` | `true` keeps the repo off the site. |
| `include` | `true` always shows a **fork**, even without commits of my own. Run `npm run sync` after changing it. |
| `group` | The tab to show it under. Any name works, for example `"Python"` or `"C / C++"`. Always wins. |
| `title`, `summary` | Replace the title (repo name with dashes as spaces) or the GitHub description. |
| `demo` | A Live demo URL, or `null` to remove GitHub's. |
| `featured`, `order` | Featured projects come first, then lower `order`, then the most recently updated. |

### Add a longer write-up to a project page

Create `content/projects/<exact-repo-name>.md` with normal Markdown.

### Add a project screenshot

Save it as `public/projects/<exact-repo-name>.webp` (or `.png` / `.jpg`). It appears on the
project's card and page automatically. A 16:9 image of about 1600 × 900 px works best.

### Company logos

The strip shows the official logos in `public/logos/` (`zertificon.svg`, `careem.png`,
`i2c.svg`, `infotech.png`). Where each one came from is recorded in
`public/logos/SOURCES.md`. Each logo is shown as a single-colour silhouette (light on
dark, dark on light), and its company name is the accessible label. If a file is
missing, the name is shown as text instead.

The logos are sized so their **letters** come out the same height, not their boxes.
Zertificon's file includes a tagline under the name, so its box is taller.
`letterRatio` in `profile.json` (under `companies`) says how much of each file's
height the letters fill; adjust it if you replace a logo.

The strip rolls continuously at one steady speed and nothing a visitor does stops it.
It only stands still for visitors who have "reduce motion" switched on.

### Skill logos

Each pill in "What I work with" shows the technology's logo from
[Devicon](https://devicon.dev) (MIT licence, installed through npm as `devicon`).
Which logo a skill uses is set by `"logos"` on that skill in `profile.json`, using
Devicon's file names, for example `"logos": ["java-plain"]` or two for a combined pill
like C/C++. Browse the names in `node_modules/devicon/icons/`. Skills without a Devicon
logo (JavaFX, InformixDB, Data Structures & Algorithms) have no `logos` and stay text
only.

The logos are drawn in the pill's text colour and turn the technology's brand colour on
hover. A brand colour that would be hard to see on the pill (below 3:1 contrast, such as
black Kafka on a dark pill or yellow JavaScript on a white one) is skipped, and that
logo keeps the text colour.

### Connect the contact form

The form posts to an external form service. Until it is connected, it shows a "not
connected yet" notice and sends nothing.

1. Create a free form at a form service, for example [Formspree](https://formspree.io).
   It gives you an endpoint like `https://formspree.io/f/abcdwxyz`.
2. In Vercel, open the project, go to **Settings → Environment Variables**, and add
   `NEXT_PUBLIC_FORM_ENDPOINT` with that URL (for Production, and Preview if wanted).
3. **Redeploy** (Deployments → ⋯ → Redeploy). The value is built into the page, so it
   only takes effect after a new build.
4. Send yourself a test message from `/contact`.

For local testing, copy `.env.example` to `.env.local` and fill in the same value.

The form sends JSON `{ name, email, message }` with `Accept: application/json`, which
Formspree and most similar services accept. A hidden honeypot field (`_gotcha`) catches
simple spam bots.

### Change the accent colours

Both accents are defined once, at the top of `src/app/globals.css`:

```css
--accent-bright: #5be3a8; /* dark theme and the black bands */
--accent-deep: #0b7a54;   /* light theme and the light Experience band */
```

Change either line and everything that uses the accent follows, including the hover
shade, which is mixed from it automatically. Keep the deep accent dark enough for
4.5:1 contrast on `#F7F7F8`.

## Deployment

Vercel builds the site with its default Next.js settings (`vercel.json` only pins the
framework). Once the repository is imported in Vercel, every push to `main` deploys to
production and pushes to other branches get preview URLs. See REVIEW.md, "Publishing".
