# Muhammad Hassan Chattha: resume and portfolio

My personal site, built with Next.js (App Router, TypeScript), plain CSS Modules
with CSS variables, Motion for scroll and hover animation, and one optional
React Three Fiber object in the hero.

## Commands

| Command         | What it does                                                                 |
| --------------- | ---------------------------------------------------------------------------- |
| `npm install`   | Install dependencies (once, and after pulling changes to `package.json`).    |
| `npm run dev`   | Development server on port 3000, reachable from other devices on the network. |
| `npm run build` | Production build (this is what Vercel runs).                                  |
| `npm run start` | Serve the production build locally.                                           |
| `npm run sync`  | Refresh `src/data/projects.json` from GitHub (needs the `gh` CLI, logged in). |
| `npm run lint`  | Check the code with ESLint.                                                   |

Requires Node.js 20.9 or newer.

### Preview on another device (for example a Mac on the same Wi-Fi)

`npm run dev` listens on all network interfaces. Open `http://<this machine's IP>:3000`
on the other device, for example `http://192.168.0.67:3000`. If the IP changes,
also update `allowedDevOrigins` in `next.config.ts`.

## Where things live

```
src/data/profile.json      everything about me: intro, about, jobs, education, skills, links, CV path
src/data/projects.json     GENERATED by `npm run sync`; never edit by hand
src/data/overrides.json    my manual changes to projects, by repo name (always win)
content/projects/*.md      optional longer write-ups for project pages
public/files/resume.pdf    the CV behind every "Download CV" button
public/images/             photos (About background, link-preview headshot)
public/logos/              company logos for the sliding strip (optional)
public/projects/           optional project screenshots

src/app/                   pages (home, /projects/[slug], /contact, /impressum, /datenschutz)
src/components/            sections, layout pieces and small UI components

```

## Common changes

### Update my details

Edit `src/data/profile.json`. Anything still marked `TODO` shows up highlighted on the
site, so it is easy to spot.

- **Switch the CV file:** put the new PDF in `public/files/` and change `"cv": { "path": ... }`,
  for example to `"/files/europass-cv.pdf"`. That one line updates every Download CV button.
- **Show or hide a profile link:** set `"show": true` or `false` on the link (Fiverr is
  currently `false`).

### Refresh projects from GitHub

```bash
npm run sync      # rewrites src/data/projects.json
git add src/data/projects.json && git commit -m "chore: sync projects" && git push
```

Private repositories and forks are always skipped. The language decides the tab:
C++ and C go to **C++**, Python and Jupyter Notebook go to **Python**, everything else
goes to **Other**. A repo's GitHub "Website" field becomes its **Live demo** link.

### Change a project without touching GitHub

Add an entry to `src/data/overrides.json`, keyed by the exact repo name:

```json
{
  "Advanced-Account-Management-System": {
    "title": "Account Management System",
    "summary": "One line about what it does.",
    "group": "C++",
    "demo": "https://example.com",
    "featured": true,
    "order": 1
  },
  "SLU": { "hide": true }
}
```

All fields are optional. `featured` projects come first, then lower `order`, then the
most recently updated. `"demo": null` removes a demo link.

### Add a longer write-up to a project page

Create `content/projects/<exact-repo-name>.md` with normal Markdown.

### Add a project screenshot

Save it as `public/projects/<exact-repo-name>.webp` (or `.png` / `.jpg`). It appears on the
project's card and page automatically. A 16:9 image of about 1600 × 900 px works best.

### Add company logos

Put the files in `public/logos/` with exactly these names:

```
zertificon.svg   careem.svg   i2c.svg   infotech.svg
```

(`.png` also works.) The site tints them to one colour that suits the theme, so a logo
with a transparent background works best. While a file is missing, the company name is
shown as text in its place. Only use logo files you are allowed to use.

### Connect the contact form

The form posts to an external form service. Until it is connected, it shows a "not
connected yet" notice and sends nothing.

1. Create a free form at a form service, for example [Formspree](https://formspree.io).
   It gives you an endpoint like `https://formspree.io/f/abcdwxyz`.
2. In Vercel, open the project, go to **Settings → Environment Variables**, and add
   `NEXT_PUBLIC_FORM_ENDPOINT` with that URL (for Production, and Preview if wanted).
3. **Redeploy** (Deployments → ⋯ → Redeploy). The value is built into the page, so it
   only takes effect after a new build.
4. Send yourself a test message from `/contact`.

For local testing, copy `.env.example` to `.env.local` and fill in the same value.

The form sends JSON `{ name, email, message }` with `Accept: application/json`, which
Formspree and most similar services accept. A hidden honeypot field (`_gotcha`) catches
simple spam bots.

### Change the accent colours

Both accents are defined once, at the top of `src/app/globals.css`:

```css
--accent-bright: #5be3a8; /* dark theme and the black bands */
--accent-deep: #0b7a54;   /* light theme and the light Experience band */
```

Change either line and everything that uses the accent follows, including the hover
shade, which is mixed from it automatically. Keep the deep accent dark enough for
4.5:1 contrast on `#F7F7F8`.

## Deployment

Vercel builds the site with its default Next.js settings (`vercel.json` only pins the
framework). Once the repository is imported in Vercel, every push to `main` deploys to
production and pushes to other branches get preview URLs. See REVIEW.md, "Publishing".
